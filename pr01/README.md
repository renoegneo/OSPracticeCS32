## Цель

Развернуть рабочее окружение Ubuntu (WSL2), создать второго пользователя и группу,
настроить права доступа к общему каталогу, на практике показать разницу между `su` и `sudo`,
настроить алиасы и переменные окружения в `.bashrc`.

## Запуск / воспроизведение

Все команды выполняются в терминале Ubuntu (WSL2) от основного пользователя, если не указано иное.

```bash
# Структура
mkdir -p ~/os-course/pr01
cd ~/os-course/pr01

# Второй пользователь и группа
sudo adduser student2
sudo groupadd developers
sudo usermod -aG developers student2
groups student2

# Общий каталог с правами
sudo mkdir /srv/shared
sudo chown root:developers /srv/shared
sudo chmod 774 /srv/shared
ls -ld /srv/shared

# Создание файла от student2
su - student2
cd /srv/shared
touch testfile.txt
ls -la
exit

# Попытка удаления от основного пользователя
rm /srv/shared/testfile.txt

# .bashrc
nano ~/.bashrc
# добавлены: alias ll='ls -la', alias update='sudo apt update && sudo apt upgrade -y',
# export COURSE_NAME="OS-basics"
source ~/.bashrc
ll
echo $COURSE_NAME
```

## Результат
**Пользователь и группа:**
```
student2 : student2 users developers
```

**Права на /srv/shared:**

**Попытка удаления файла от основного пользователя:**

## Выводы

**Почему `rm` вернул Permission denied.** Право на удаление файла определяется правами
не самого файла, а директории, в которой он лежит (удаление — это запись в директорию:
"такого файла больше нет"). У `/srv/shared` установлены права `774` — владелец (root) и
группа (developers) имеют rwx, а категория "остальные" — только `r--`, без права записи.
Основной пользователь не входит в группу `developers`, поэтому для этой папки попадает
в категорию "остальные" и не может ни создавать, ни удалять файлы — только читать.
Это и есть ожидаемое поведение задания.

**`su` vs `sudo`.**
`sudo <команда>` выполняет одну конкретную команду с правами root (или другого пользователя
через `-u`), после чего сессия сразу возвращается в исходное состояние. Запрашивает пароль
самого вызывающего пользователя (если он есть в sudoers).

`su - <пользователь>` полностью переключает текущую сессию на другого пользователя до команды
`exit`. Запрашивает пароль того пользователя, на которого переключаются.

**Почему в Ubuntu по умолчанию заблокирован вход под root.** У root в Ubuntu изначально нет
заданного пароля, то есть прямой логин под root невозможен в принципе. Все административные
действия обязаны проходить через `sudo` от имени обычного пользователя — это значит, что
каждое такое действие остаётся привязанным к конкретному человеку и попадает в лог с его
именем, а не обезличенно от root. Это упрощает аудит и снижает риск случайных разрушительных
действий, которые легко допустить, находясь в root-сессии по умолчанию.
