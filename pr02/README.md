## 1. report.sh

Вызов: `./report.sh <каталог> <ERROR|WARN> [--top N]`

Как работает: `awk` за один проход считает записи заданного уровня по полю `$4` (`module=...`), `sort` упорядочивает по убыванию, второй `awk` оформляет таблицу и обрезает её до N строк.

### Примеры

`./report.sh data ERROR`
```
MODULE     COUNT
--------------------
db         637
net        600
disk       321
auth       269
api        152
cache      116
fs         76
sched      74
```

`./report.sh data ERROR --top 3`
```
MODULE     COUNT
--------------------
db         637
net        600
disk       321
```

`./report.sh data WARN`
```
MODULE     COUNT
--------------------
net        933
disk       889
db         740
cache      647
api        461
auth       438
sched      215
fs         203
```

### Обработка ошибок
Во всех случаях справка печатается в stderr, код возврата 1.

| Команда | Причина |
| --- | --- |
| `./report.sh` | нет аргументов |
| `./report.sh data` | нет уровня |
| `./report.sh data INFO` | недопустимый уровень |
| `./report.sh /nope ERROR` | каталог не существует |
| `./report.sh data ERROR --top` | после `--top` нет числа |
| `./report.sh data ERROR --top abc` | N не число |
| `./report.sh data ERROR --top 0` | N меньше 1 |

Граничные случаи: `25.log` пустой, а в `08.log` нет строк ERROR. Скрипт обрабатывает их без особых проверок, потому что считает через `awk`, а не через `grep -c` (у того на нулевом результате код возврата 1).

Проверка: `shellcheck -S error report.sh` ошибок не выявил (код возврата 0).

### Вывод по данным
По сумме ERROR лидирует `db` (637), но это обманчиво: в `17.log` в интервале 14:00–15:00 был всплеск, +120 ошибок `db`. Без него у `db` было бы 517, и лидером стал бы `net` (600). Значит, устойчиво проблемный модуль это `net`, а `db` это один инцидент.

## 2. hello.py
`./hello.py data/01.log` → `data/01.log: 19076 байт` (совпадает с `wc -c`).

## 3. Анализ strace (`trace.txt`, `trace_cat.txt`)

| | python3 hello.py | cat |
| --- | --- | --- |
| Всего системных вызовов | 559 | 119 |
| Вызовов, связанных с файлом | 9 | 6 |
| Из них собственно `read` | 2 | 2 |

Вызовы считались командой `grep -cE '^[0-9]+ +[a-z_0-9]+\(' trace.txt`; строки `+++ exited +++` не учитывались.

**Сколько всего системных вызовов:** 559.

**Сколько относится к чтению файла:** 9 (`openat`, `fstat`, `ioctl`, `lseek` ×2, `fstat`, `read` ×2, `close`). Собственно чтением являются два `read`: первый вернул все 19076 байт файла, второй вернул 0 (конец файла). Ещё один `write` выводит результат на экран.

**Почему остальные (550) это накладные расходы интерпретатора:** до строки `hello.py` Python успевает загрузить libc и себя самого, инициализировать обработчики сигналов (`rt_sigaction`), найти и прочитать стандартные модули (`openat`, `newfstatat`, `read`, `mmap` по пути импорта), настроить память. Всё это не зависит от того, какой файл мы читаем, и происходит при каждом запуске.

## 4. Сравнение cat и python3

`cat` сделал 119 вызовов, `python3` 559, то есть в ~4,7 раза больше на одну и ту же полезную работу. На сам файл оба тратят почти одинаково (6 и 9 вызовов, по 2 `read`). Разница целиком набегает на старте: `cat` это маленькая скомпилированная программа, которой нужна только libc, а Python перед своей работой поднимает всё окружение интерпретатора. Вывод: удобство языка высокого уровня оплачивается системными вызовами на запуске, поэтому для коротких утилит, запускаемых много раз, компилируемые программы выгоднее.

## 5. Контрольные вопросы

**Почему нельзя обратиться к диску напрямую из пользовательской программы?**
Инструкции работы с устройствами привилегированные, а процессор выполняет пользовательский код в ограниченном режиме. Доступ к диску возможен только через ядро (системные вызовы), которое проверяет права, изолирует процессы друг от друга и координирует общий доступ к устройству.

**Что дороже: вызов функции или системный вызов?**
Системный вызов. Обычный вызов функции это переход внутри программы в пользовательском режиме. Системный вызов требует переключения в режим ядра: сохранить состояние, проверить аргументы, выполнить работу и вернуться. Поэтому он на порядки дороже, и им стараются не злоупотреблять (буферизация, чтение крупными блоками).
